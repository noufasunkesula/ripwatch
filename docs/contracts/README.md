# RipWatch contracts

The messages that pass between vision, the agent, `rw-api` and the dashboard. The Pydantic models in `rw/contracts/` are the source of truth. The `*.schema.json` files in this folder are generated from them. Do not edit them by hand.

| Contract | Model | Schema | Written by | Read by |
|---|---|---|---|---|
| VisionResult v1.0 | `rw.contracts.vision.VisionResult` | `vision-result.schema.json` | `rw-vision` | agent, MCP tools, dashboard |
| CandidateMessage v1.0 | `rw.contracts.candidate.CandidateMessage` | `candidate-message.schema.json` | `rw-vision` (SQS `rw-candidates`) | agent |
| AgentDecision v1.0 | `rw.contracts.decision.AgentDecision` | `agent-decision.schema.json` | agent | `rw-api`, dashboard |
| TraceStep v1.0 | `rw.contracts.trace.TraceStep` | `trace-step.schema.json` | agent (`rw-agent-trace`) | `rw-api`, dashboard |
| Approval v1.0 | `rw.contracts.decision.Approval` | `approval.schema.json` | `rw-api` (`rw-approvals`) | agent, dashboard |
| Job v1.0 | `rw.contracts.vision.Job` | `job.schema.json` | ingest, `rw-api` (`rw-jobs`) | ingest, dashboard |

Field-by-field definitions are in `docs/sprints/sprint-1.md` section 7.

## Rules every model follows

- Unknown fields are rejected (`extra="forbid"`).
- Every fixed value is an enum.
- IDs are prefixed ULIDs (`res_`, `tr_`, `job_`, `inc_`, `dec_`), generated by `rw.common.ids`.
- Timestamps must carry a timezone and are serialized as UTC with a `Z` suffix.
- Lists are empty, never `null`.
- Metre fields (`*_m`, `*_m_per_s`, `position_m`) stay `null` unless the camera has a calibration homography.

VisionResult has these extra checks:

- `summary.status` and every `rips[].label` must match the confidence thresholds. The defaults are 0.70 for rip and 0.40 for uncertain. Pass the live SSM values with `VisionResult.model_validate(data, context={"rip_threshold": ..., "uncertain_threshold": ...})`.
- Polygons have 3 to 32 points, all inside `input.width` x `input.height`.
- There are at most 10 keyframes.
- `rip_count` and `swimmer_count` must match the list lengths.
- A swimmer's `in_rip_id` must point to a rip in the same result.
- Motion fields (`seaward_flow_*`, `drift_px_per_s`) must be `null` in `image` mode.
- The serialized size must be under 64 KB.

## Versioning

Every contract has `schema_version`.

| Change | Bump | Approval |
|---|---|---|
| Add an optional field (with a default) | Minor: `1.0` to `1.1` | Owner + reviewer |
| Remove or rename a field, change a type, add a required field, narrow an enum | Major: `1.x` to `2.0` | Both owners |
| Tighten or loosen a validator without changing the schema shape | None, but note it in the PR | Owner + reviewer |

During a version change, readers must accept the old and new versions until every writer has been deployed.

## How to propose a change

1. Open an issue or a `handoff.md` Request that says what you need, why you need it, and which contract version it changes.
2. Edit the model in `rw/contracts/`, bump `schema_version` if needed, and update the tests in `tests/unit/contracts/`.
3. Regenerate the schemas with `python -m rw.contracts.export_schemas` and commit them in the same PR. CI runs `python -m rw.contracts.export_schemas --check` and fails if the committed schemas are out of date.
4. Log the decision in the sprint Decision Log with the date and who approved it.
